# コスめぐり

**レイヤーの一日エージェント。** コスプレ遠征の準備から当日までを、ひとつの相談窓口にまとめる。

X の DM とスプレッドシートで回っている「合わせの幹事業務」と、紙と行列のままの
「更衣室運用」をエージェント化する。設計の背景と判断は [設計書.md](設計書.md)、
開発の手順と決めごとは [CONTRIBUTING.md](CONTRIBUTING.md)、
Cloud Run への載せかたは [DEPLOY.md](DEPLOY.md) を参照。

![技術スタック](docs/architecture.png)

赤い線だけが自律起動（Cloud Scheduler → 当日モードの進行 / TTL削除）。他はすべて利用者の操作起点。

## 画面

「AIに相談」のチャットはどのページでも右に開いたまま。左端のシェブロンで4つの節を行き来する。

| ページ | 中身 |
|---|---|
| `/` | できること・使い方・ログイン |
| `/prep` | 顔の登録と試着の候補 |
| `/plan` | メイクの工程・動線・更衣室 |
| `/looks` | 完成イメージと音声ガイド |
| `/day` | 当日のようすと合わせ |

## できること

チャットに「9/6のコミケに横浜駅から行きます。大荷物です」と書くと、足りない条件だけを
聞き返しながら、一日ぶんを組み立てる。

- **キャラ再現メイクの手順化** — Fitzpatrick 肌タイプと顔属性から9工程を個別化する。
  肌が濃ければ白浮きを避ける下地と影色、虹彩が濃ければベース入りカラコン、離れ目なら目頭側にライン。
  **肌の明るさ自体を変える指示は出さない**（キャラの色味には光と影で寄せる）
- **大荷物制約の動線** — 階段と乗換を体感時間に換算し、最短ではなく **EV被覆の高い順**で経路を選ぶ。
  大型ロッカーの預け先も提案する
- **更衣室の混雑予測** — イベント規模と収容から入場・撤収の推奨時刻を出す（実測ではない予測であることを常に明示。画面では「予測」と出す）
- **試着** — キャラからウィッグ・衣装の候補を出す。確定するのは利用者
- **合わせの幹事業務** — 招集・進捗・到着監視・撮影枠のリスケ起案。**枠の確定は主催者の承認を通す**
- **多言語** — UIも工程も母語で出す（日英）。イベント慣習・更衣室ルールの文化的な補足つき
- **完成イメージ** — ウィッグ×衣装×メイクの完成予想図を生成。製作・購入の前に方向性を確かめられる
- **音声ガイド** — 移動中とメイク中は画面を見られない。工程と動線を母語で読み上げる
- **アフタームービー** — 合わせの撮影写真から短いPVを起こす（合わせの締めの文化をエージェント化）

## プライバシー

コミュニティ固有の要求を設計の中心に置いている。

- **アカウントはコス名だけで成立する。** 本名も素顔も預からない
- **顔画像は解析後に破棄する。** 残すのは肌タイプと顔属性の数値だけで、破棄したことも記録に残る
- **位置共有はイベント当日限定。** 終了24時間後に履歴ごと自動削除される
- **外部メッセージングを使わない。** LINE も X も繋がない。当日の通知はアプリ内のお知らせ欄で完結し、
  電話番号も端末トークンもSNSアカウントも持たない
- **キャラ名・作品名はメイク工程の生成にだけ使う。** 外向きの応答にも、画像生成のプロンプトにも出さない
- **生成物にはAI生成であることを明示する。** ボイスクローンは使わない（キャラクター音声の権利リスクを構造的に回避）

## 動かす

```bash
docker compose up api
```

`http://localhost:8080` を開く。**APIキーが1本も無い状態でも一日ぶんのフローが最後まで通る**
（未設定のプロバイダは自動的にモックで動く）。ログインも既定は開発用で、コス名を入れるだけで始められる。
データは同時に起動する Firestore エミュレータに入るので、再起動しても残る。

セットアップの詳細・テスト・実APIへの差し替えは [CONTRIBUTING.md](CONTRIBUTING.md) を参照。

## 現時点の制約

- **更衣室の混雑は実データ非連携のモデル値**。イベント規模と収容から算出しており、応答には常に
  「予測」の印が付く
- **当日の通知はアプリを開いて確認する必要がある**（Web Push は未実装）
- 対応言語は日英。中韓は設定の追加だけで有効になる
- 主催者向けの更衣室ダッシュボードは未実装

技術面の未検証事項は [CONTRIBUTING.md の引き継ぎ事項](CONTRIBUTING.md#未検証引き継ぎ事項) にまとめてある。
